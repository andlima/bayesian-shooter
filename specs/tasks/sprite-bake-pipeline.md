# Sprite Bake Pipeline — PNG-Source Enemies (imp + grunt)

## Goal

Replace the hand-written ASCII-art definitions of the `imp` and `grunt`
enemy sprites with a small offline asset pipeline: real `.png` source
files under `assets/sprites/`, a zero-dependency Node bake script that
inlines their pixels into a sentinelled region of `index.html`, and a
`Makefile` with `bake` and `serve` targets. This is the
"separate-sources, single-file output" approach: contributors edit PNGs
in a pixel-art editor and run one command; players and forkers still get
a single `index.html` that opens over `file://` with no build step.

This task ships the **pipeline**, seeded with the **current** imp/grunt
art re-expressed as PNGs, so it is a pure infrastructure change with
**zero rendered-pixel difference**. Swapping in external CC0 art later
becomes a one-step follow-up (replace PNGs, `make bake`).

## Why not download CC0 art in this task

The autonomous implementation sandbox's network allowlist does not
include Kenney.nl, OpenGameArt.org, or itch.io, so the implementing
agent cannot fetch external art. Rather than block, this task delivers
the reusable pipeline and seeds it with the existing art (pixel-identical
bootstrap). This makes the acceptance criteria **objectively testable
without a browser** (inflated arrays must equal the old procedural
output element-for-element) and leaves a documented, trivial path to
drop in real CC0 sprites afterward.

## Acceptance Criteria

1. **New files exist:**
   - `assets/sprites/imp_1.png`, `assets/sprites/imp_2.png`,
     `assets/sprites/grunt_1.png`, `assets/sprites/grunt_2.png` —
     each a valid 32×32 RGBA PNG (8-bit, color type 6).
   - `tools/bake-sprites.mjs` — Node ESM, **zero npm dependencies**
     (only `node:fs`, `node:path`, `node:zlib`, `node:url`). Must run
     under the repo's Node (v24, confirmed available).
   - `assets/CREDITS.md` — scaffold stating the seeded art is derived
     from the repo's prior procedural generators and describing how to
     attribute CC0 art when the PNGs are later replaced.
   - `Makefile` at repo root.

2. **`tools/bake-sprites.mjs` has two modes:**
   - `node tools/bake-sprites.mjs --bootstrap`: writes the four PNGs
     above from ASCII sprite definitions embedded in the script. These
     definitions must reproduce the **exact** current `impFrame1`,
     `impFrame2`, `gruntFrame1`, `gruntFrame2` pixels (same palettes,
     same rows as `index.html:1580-1732`). Used once to seed sources
     without network access. Must not overwrite existing PNGs unless
     `--force` is also passed.
   - `node tools/bake-sprites.mjs` (default): decodes the four PNGs and
     rewrites **only** the region of `index.html` between the sentinels
     (see criterion 3). Every byte of `index.html` outside the sentinel
     region is unchanged. Running it twice in a row produces no further
     diff (idempotent, deterministic output — sorted keys, fixed wrap).

3. **`index.html` runtime change:**
   - Remove the `impPalette`, `impFrame1`, `impFrame2`, `gruntPalette`,
     `gruntFrame1`, `gruntFrame2` definitions (`index.html:1580-1732`).
     Leave `buildFrame` and every other procedural sprite (`exitFrame`,
     `impProjFrame`, `gruntProjFrame`, medkit/ammo pickups) **untouched**.
   - Insert a sentinelled, generated region. Exact sentinel lines:
     ```
     // <BAKED_SPRITES_BEGIN> generated by tools/bake-sprites.mjs — do not edit by hand
     ...generated content...
     // <BAKED_SPRITES_END>
     ```
   - The generated content defines, per frame, a base64 string of the
     raw little-endian `Uint32Array` bytes (the same `0xAARRGGBB`
     packing produced by `rgba32`, `0` = fully transparent), plus a
     **synchronous** inflater that turns each base64 string back into a
     `Uint32Array(SPRITE_SIZE * SPRITE_SIZE)` and assigns the frame
     pairs so that `SPRITES.imp` and `SPRITES.grunt` resolve exactly as
     before. No `Image()`, no `fetch`, no `<canvas>` decode, no
     `await` — startup stays synchronous.
   - `SPRITES` registry shape, the sprite renderer (`drawSprites`,
     `index.html:3629`), the 2-frame ~4Hz animation, and the per-column
     z-buffer billboard pipeline are all unchanged.

4. **Zero visual regression (objective):** the inflated `imp` and
   `grunt` frame `Uint32Array`s are **element-for-element identical** to
   the pre-change procedural output. The implementing agent must capture
   the four expected arrays before editing (e.g. by evaluating the
   current `buildFrame` blocks in Node, or extracting them from the
   running page) and verify equality after the change. Document the
   verification method used in the PR/commit body.

5. **Invariants preserved:**
   - `index.html` is still a single file and still opens correctly via
     `file://` (no network/async added for these sprites).
   - The seeded-LCG byte-identical-first-frame property holds: sprite
     data is static; no `Math.random()` is introduced on any sprite
     path.
   - `index.html` byte-size growth is bounded (well under 25 KB).

6. **Makefile** (repo root) provides exactly:
   - `make bake` → `node tools/bake-sprites.mjs`
   - `make serve` → serves the repo root over HTTP on the default port
     (`python3 -m http.server`)
   - Both declared `.PHONY`. No other targets are required (no `help`,
     no `check`).

7. **Docs:** `AGENTS.md` gains a short "Asset Baking" subsection
   documenting the PNG-source → `make bake` flow and the sentinel
   contract. Do not duplicate this into `CLAUDE.md` (keep `CLAUDE.md`
   additive and non-contradictory per its own rule).

## Out of Scope

- Downloading or adding real external CC0 art (network-blocked in the
  sandbox; this task seeds with the existing art). Replacing the PNGs
  with CC0 sprites is a deliberate follow-up.
- Any change to rendered pixels. This task must be visually a no-op.
- Pickups, gun viewmodel, exit beacon, projectiles, and wall/floor/
  ceiling textures — all stay procedural and untouched.
- `make check` / CI drift-detection, `make help`, and any GitHub
  Actions integration.
- Splitting JS out of `index.html`, adding a bundler, or any runtime
  build step.
- npm/yarn dependencies of any kind (the bake script must be zero-dep).

## Design Notes

- Pixel format: `rgba32` (`index.html:883`) packs little-endian with
  R in the least-significant byte and A in the most-significant
  (`0xAARRGGBB` as a JS number, R = LSB in memory). A fully transparent
  pixel is the word `0`. The PNG decoder must convert decoded RGBA8
  samples to this exact word; the inflater must reproduce the same words
  the old `buildFrame` produced. PNG alpha 0 → word `0`.
- Node 24 has `zlib.deflateSync` / `zlib.inflateSync` built in, so both
  a minimal PNG encoder (for `--bootstrap`) and decoder (for the bake)
  are achievable with zero deps. Keep the PNG handling minimal: 8-bit,
  color type 6 (RGBA), no interlace, single `IDAT`, filter type 0 per
  scanline is sufficient for the encoder; the decoder should handle the
  standard filter types (0–4) defensively but the bootstrap encoder may
  emit only filter 0.
- Sentinel rewrite must be a precise text splice: find the BEGIN/END
  marker lines, replace everything strictly between them, preserve
  surrounding indentation and the two marker lines' exact text.
  Deterministic output (stable key order, fixed base64 line wrapping or
  a single line per frame) so re-running `make bake` yields no diff.
- The `--bootstrap` ASCII definitions are the *only* place the old imp/
  grunt art survives after this change; copy the rows verbatim from
  `index.html:1580-1732` before deleting them so the bootstrap is
  pixel-exact.
- `SPRITE_SIZE` is `32` (`index.html:1565`). Frames are
  `Uint32Array(SPRITE_SIZE*SPRITE_SIZE)` = 1024 words = 4096 bytes;
  base64 ≈ 5.5 KB per frame, ~22 KB for four frames before any
  whitespace — within the size budget.

## Agent Notes

- Read `AGENTS.md` (esp. Worktree-Only Editing) and the sprite section
  of `index.html` (`1561-2027`) and the renderer (`drawSprites`,
  ~`3629`) before editing.
- Suggested order:
  1. Snapshot expected arrays: copy the four imp/grunt `buildFrame`
     blocks + their palettes, evaluate in a scratch Node script, and
     save the four `Uint32Array`s as the regression oracle.
  2. Write `tools/bake-sprites.mjs` with the embedded ASCII defs
     (verbatim from `index.html:1580-1732`), PNG encode/decode, the
     sentinel splicer, and `--bootstrap`/`--force` flags.
  3. `node tools/bake-sprites.mjs --bootstrap` → produces the 4 PNGs.
  4. In `index.html`, delete the imp/grunt ASCII blocks and insert the
     sentinel region (BEGIN/END markers with a placeholder body).
  5. `node tools/bake-sprites.mjs` → fills the sentinel region.
  6. Verify: inflate in Node and assert element-wise equality against
     the step-1 oracle for all four frames; assert idempotency (run
     bake twice → no diff); assert nothing outside the sentinels moved.
  7. Add `Makefile`, `assets/CREDITS.md`, the `AGENTS.md` subsection.
- Common pitfalls: byte order (R vs B) in the PNG↔word conversion;
  transparent pixels must be the word `0` not an opaque black; the
  inflater must be synchronous and run before the first frame; do not
  touch `exitFrame`/projectile/pickup `buildFrame` calls; keep the two
  sentinel marker lines byte-stable so future bakes are clean diffs.
- Self-verification is fully offline (Node + reading the file). A
  browser is not required to prove this task, since it is a guaranteed
  visual no-op when criterion 4 passes — but if convenient, `make serve`
  and confirm imp/grunt still render and animate.
