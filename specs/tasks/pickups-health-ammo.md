# Pickups (health + ammo)

## Goal

Give the dungeon a reason to explore each room beyond the exit-seek. Add
two pickup categories (health, ammo) with two tiers each (small, large)
that spawn in non-starting rooms during dungeon generation. The player
walks over a pickup to consume it; the grant is clamped to `MAX_HP` /
`MAX_AMMO`. If already at max, the pickup is left in place. Pickups are
deterministic from the dungeon seed (same seed → same layout), restored
by R-on-death, and regenerated by N and by stepping on the exit.

Functional contract everywhere else stays: HP and ammo caps, contact
damage, enemy AI, projectile pipeline, sprite z-buffer, fog/lighting,
minimap geometry, kill pops, level banner, HUD strip, gun viewmodel,
audio unlock, touch controls, mute behaviour, exit-step progression —
all unchanged.

7. **Pickup placement in `generateDungeon`.** Add a placement block
   immediately after the enemy-spawn block (`index.html:2004-2033`) and
   before the `return { ... }` line (`index.html:2035`). Reuses the
   same seeded `rand()` so layout is deterministic per seed:
   ```js
   // pickups-health-ammo: 0-2 per non-starting room. Avoids cells
   // already claimed by enemy spawns in the same room.
   const newPickupSpawns = [];
   for (let i = 0; i < rooms.length && newPickupSpawns.length < MAX_PICKUPS; i++) {
     if (i === startIdx) continue;
     const room = rooms[i];
     // Enemy cells in this room (Set keyed on "y,x"); excluded from pickup cells.
     const taken = new Set();
     for (let n = 0; n < newSpawns.length; n++) {
       const sp = newSpawns[n];
       const cx = Math.floor(sp.x), cy = Math.floor(sp.y);
       if (cx >= room.x && cx < room.x + room.w &&
           cy >= room.y && cy < room.y + room.h) {
         taken.add(cy + ',' + cx);
       }
     }
     const cells = [];
     for (let y = room.y; y < room.y + room.h; y++) {
       for (let x = room.x; x < room.x + room.w; x++) {
         if (map[y][x] === 0 && !taken.has(y + ',' + x)) cells.push({ x, y });
       }
     }
     for (let s = cells.length - 1; s > 0; s--) {
       const j = Math.floor(rand() * (s + 1));
       const tmp = cells[s]; cells[s] = cells[j]; cells[j] = tmp;
     }
     const count = Math.floor(rand() * (PICKUP_MAX_PER_ROOM + 1)); // 0..2
     const take = Math.min(count, cells.length);
     for (let k = 0; k < take && newPickupSpawns.length < MAX_PICKUPS; k++) {
       const cell = cells[k];
       const tier = rand() < PICKUP_LARGE_CHANCE ? 'large' : 'small';
       const kind = rand() < 0.5 ? 'health' : 'ammo';
       newPickupSpawns.push({
         x: cell.x + 0.5,
         y: cell.y + 0.5,
         type: kind + '_' + tier,
       });
     }
   }
   ```
   Include `pickupSpawns: newPickupSpawns` in the returned object
   alongside `enemySpawns`. The roll order (`tier` before `kind`) is
   the contract — changing it changes the seeded layout, which would
   alter the meaning of `?seed=...` URLs reported in console.

11. **Walk-on pickup check.** Add `applyPickups()` near
    `applyContactDamage` (`index.html:2442-2479`) and call it from
    `update()` right after `applyContactDamage(dt)`
    (`index.html:805`):
    ```js
    function applyPickups() {
      if (player.hp <= 0) return;
      const r2 = PICKUP_RADIUS * PICKUP_RADIUS;
      for (let i = 0; i < pickups.length; i++) {
        const p = pickups[i];
        if (!p.alive) continue;
        const dx = p.x - player.x;
        const dy = p.y - player.y;
        if (dx * dx + dy * dy > r2) continue;
        if (p.type === 'health_small' || p.type === 'health_large') {
          if (player.hp >= MAX_HP) continue;   // skip-if-full: leave for later
          const amt = (p.type === 'health_large') ? PICKUP_HEALTH_LARGE : PICKUP_HEALTH_SMALL;
          player.hp = Math.min(MAX_HP, player.hp + amt);
          spawnPickupPop(p.x, p.y, '+' + amt + ' HP', 'health');
          sfxPickupHealth();
          p.alive = false;
        } else if (p.type === 'ammo_small' || p.type === 'ammo_large') {
          if (ammo >= MAX_AMMO) continue;       // skip-if-full
          const amt = (p.type === 'ammo_large') ? PICKUP_AMMO_LARGE : PICKUP_AMMO_SMALL;
          ammo = Math.min(MAX_AMMO, ammo + amt);
          spawnPickupPop(p.x, p.y, '+' + amt + ' AMMO', 'ammo');
          sfxPickupAmmo();
          p.alive = false;
        }
      }
    }
    ```
    Single pass — multiple pickups at the same cell are extremely
    unlikely (cells are distinct per room) but if they ever occur all
    valid grabs in radius are consumed in one frame.

    "Skip if full" semantics: if the player walks over a health pickup
    at exactly `player.hp === MAX_HP`, the pickup stays. Partial fill
    (e.g. HP=90, small medkit grants 25) is accepted and clamped to
    100 — the pickup is consumed because it had effect.

    ```js
    function drawPickupPops() {
      if (pickupPops.length === 0) return;
      const invDet = 1 / (player.planeX * fovPunch * player.dirY - player.dirX * player.planeY * fovPunch);
      const halfW = W >> 1;
      const halfH = H >> 1;
      ctx.font = '10px monospace';
      ctx.textBaseline = 'middle';
      ctx.textAlign = 'center';
      for (let i = pickupPops.length - 1; i >= 0; i--) {
        const p = pickupPops[i];
        if (nowMs >= p.untilMs) { pickupPops.splice(i, 1); continue; }
        const t = (nowMs - p.atMs) / (p.untilMs - p.atMs);
        const camX = p.x - player.x;
        const camY = p.y - player.y;
        const transformX = invDet * (player.dirY * camX - player.dirX * camY);
        const transformY = invDet * (-player.planeY * fovPunch * camX + player.planeX * fovPunch * camY);
        if (transformY <= 0) continue;
        const screenX = (halfW * (1 + transformX / transformY)) | 0;
        const screenY = (halfH - 16 * t) | 0;          // float up ~16 px
        const a = 1 - t;
        const tint = (p.color === 'health') ? '180,255,200' : '255,230,140';
        ctx.fillStyle = `rgba(0,0,0,${(a * 0.7).toFixed(3)})`;
        ctx.fillText(p.text, screenX + 1, screenY + 1);
        ctx.fillStyle = `rgba(${tint},${a.toFixed(3)})`;
        ctx.fillText(p.text, screenX, screenY);
      }
      ctx.textAlign = 'left';
      ctx.textBaseline = 'top';
    }
    ```

## Out of Scope

- **Armor / shield / temporary buff pickups.** Health and ammo only
  for this task. A future spec could add `armor_small / armor_large`
  with a new `player.armor` stat; that's an additive change against
  the same pipeline.
- **Key / unlock-door pickups.** No locked doors in the dungeon today.
- **Animated pickups** (bob / glow / pulse). Both `SPRITES[type]`
  entries are the same frame; static rendering is fine. A pulse /
  bob is a polish follow-up.
- **Pickup variety per room.** Pickups are distributed independently
  per room with uniform 0/1/2 quantity and a 50/50 health-vs-ammo
  roll. No "this room only has ammo, this room only has health"
  themed distribution.
- **Pickup-on-enemy-kill drops.** Enemies drop neither pickups nor
  the existing `AMMO_REFUND` mechanic moves to a drop model. The
  `+3` ammo on kill is unchanged; pickups are purely
  generation-placed.
- **Re-tuning HP / ammo combat numbers.** `MAX_HP`, `MAX_AMMO`,
  `SHOT_DAMAGE`, `CONTACT_DPS`, `AMMO_REFUND`, enemy stats — all
  unchanged.
- **Pickup persistence across R-reset.** The user chose
  "treat-like-enemies" semantics: R restores the original pickup
  layout (and consumed-stays-consumed is explicitly *not* the
  contract).
- **Touch HUD pickup indicator.** No new affordances on the touch
  HUD. Existing util row / RESET / joystick are unchanged. Pickup
  feedback is the worldspace pop + audio.
- **A pickup-count or pickup-rate stat.** `stats` schema
  (`shotsFired / shotsHit / kills / deaths / enemyShotsFired /
  enemyShotsHit`) is the contract for the future Bayesian-skill spec
  and is left untouched.
- **Pickup despawn / time-decay.** Pickups exist until consumed or
  until N / exit-step regenerates the dungeon. No TTL.
- **Per-enemy-cell exclusion at generation time across multiple
  rooms.** Pickups can spawn in the same cell where an enemy from
  *another* room transiently is — that's impossible in practice
  because enemies are placed at room-interior cells and rooms don't
  overlap, but the exclusion check (AC #7) is per-room only by design.

## Design Notes

- **Why pickups in the existing sprite pipeline.** The existing
  `drawSprites` already supports a duck-typed entity model (enemy /
  projectile / synthetic exit) keyed on `o.e.type` into `SPRITES`.
  Pickups slot in as a 4th entity category with no renderer changes —
  the only addition is the push loop. id offset `2000` keeps the
  stable-sort tiebreak deterministic across the four categories
  (enemies 0..N, projectiles 1000..1000+M, pickups 2000..2000+P,
  exit -1).

- **Why 16×16 sprites with content biased to the lower half.** The
  sprite renderer centers each sprite vertically at `halfH = H / 2`,
  which is the player's eye level in the raycaster's projection. A
  pickup that physically sits on the floor should therefore render
  *below* eye level. Biasing the visible pixels to rows 8-15 (small)
  or 4-15 (large) of the 16×16 frame puts the sprite's center of
  mass below halfH → "on the ground" reads naturally. The
  alternative (per-sprite `vOffset` field) would require a new
  parameter through the entire sprite renderer, which is heavier than
  the visual change deserves.

- **Why 0-2 per room, uniform.** `Math.floor(rand() * 3)` gives 0, 1,
  or 2 with equal probability — a third of non-starting rooms have
  no pickups (rewarding exploration vs. handing things out), a third
  have one, a third have two. At the existing dungeon size
  (`TARGET_MIN = 6` rooms, typical 8-12 rooms placed) this puts
  6-15 pickups per dungeon, well under the `MAX_PICKUPS = 18` cap.

- **Why tier roll before kind roll.** Ordering matters for the seeded
  PRNG: the spec contract is that `?seed=1234` produces the same
  dungeon layout (walls, enemies, pickups) reload-after-reload. The
  roll order (`tier`, then `kind`) is the contract — implementer
  must not reorder.

- **Why exclude cells claimed by enemies in the same room.** Two
  reasons. (1) Visual: an enemy sprite sitting on top of a pickup
  sprite at the same cell renders as one composite blob; the player
  can't see the pickup until they kill the enemy, which is fine but
  fiddly to read. (2) Gameplay: walking up to the enemy to melee /
  point-blank fire would also grab the pickup as a side effect, which
  reads as a free reward for taking damage. Excluding makes the two
  systems independent. The "taken" Set is built per room — pickup
  generation across rooms is order-independent of which enemies were
  placed in *other* rooms.

- **Why "skip if full" instead of "consume always".** The user chose
  this option. It gives the player tactical resource management —
  noting a large medkit's location and coming back to it after a hit
  — at the cost of one extra branch in `applyPickups`. The cost is
  trivial; the gameplay impact is real.

- **Why per-type SFX (sine rise vs. square-rise blip).** A rising
  sine chime reads as "healing / positive" by genre convention; a
  short square click reads as "mechanical / loading". The two are
  acoustically distinct enough that the player can tell what they
  grabbed without looking at the HUD — useful when pickups are
  grabbed mid-combat. Both peaks are well under the existing
  `sfxShot` peak (0.7) so they don't drown the gunfire.

- **Why green for health dots, yellow for ammo dots.** Health =
  green is a hard convention; ammo = yellow / brass reads as "shell
  casings". The minimap already uses red for enemies (`#f33`) and
  bright green (`#3f3`) for the exit cell — picking `#3c8` (a
  slightly muted green) for health avoids confusion with the exit
  square, and `#fc3` (gold yellow) is distinct from the player
  triangle's `#ff0`.

- **Why 600 ms pop duration (vs. kill pop's 500 ms).** The pickup pop
  text is longer (`+25 HP` is 5 chars + `+14 AMMO` is 8 chars) than
  the kill pop's `+1` (2 chars). A slightly longer hold lets the
  player read it while the floating-up animation completes. 16 px
  rise over 600 ms (~27 px/s) matches the kill pop's 12 px / 500 ms
  (~24 px/s) — both feel like the same "rising text" speed.

- **Why no pop / sfx when skipped at full.** Reinforces the
  "leave-it-for-later" feel — if the player walks over a medkit at
  full HP and gets a chime, they'd assume it grabbed something. No
  audio / no visual cue → "this object is still there" reads
  cleanly. The minimap dot remains visible after the failed grab.

- **Why pickups don't pause / reset enemy AI when grabbed.** Pickups
  are a pure additive grant; nothing in the enemy / projectile /
  level pipeline cares about them. The pickup's `alive = false`
  marks it dead; `drawSprites` skips it; the minimap skips it; the
  pickup-pop renders for `PICKUP_POP_MS` and is then GC'd.

- **Edges to verify:**
  - HP=99, walk over small medkit (+25) → HP=100, pickup consumed,
    "+25 HP" pop appears, sound plays. (Partial grant is accepted.)
  - HP=100, walk over small medkit → no grant, no pop, no sound,
    pickup stays. Step away then back: still present. (Skip-if-full.)
  - Ammo=24 (MAX), walk over small ammo → no grant, pickup stays.
  - Ammo=23, walk over small ammo (+6) → ammo=24, pickup consumed.
  - Walk over a pickup while contact-damage tickling at HP=12, small
    medkit (+25) → HP=37, pickup consumed, vignette flash continues
    on next damage tick. Pickup grant does *not* clear the damage
    flash.
  - Walk over a pickup with `player.hp = 0` (mid-death-frame) →

  - Walk over a pickup at HP=100 → step onto adjacent exit cell →

    skipped pickup from the prior level is gone (new spawns
    replace it).
  - `?seed=4567` two reloads → identical pickup positions, types,

- **Hot-path discipline.** `applyPickups` does one squared-distance
  test per pickup per frame (no `Math.sqrt`). The pickup-pop
  pipeline mirrors kill pops byte-for-byte (no new alloc patterns).
  Pickup minimap dots are inside the existing `clip()` region so no
  extra `save / restore` is needed. No per-frame allocations.

- **Common pitfalls:**
  - **Forgetting to reset `pickupPops` in `clearTransientFeedback`.**
    A pop from level N can render against the wrong player.x / y
    after `advanceLevel` and look glitchy. AC #10 covers this.
  - **Building `pickups` from `enemySpawns` by accident.** Both
    spawn arrays look similar; the `resetRun` / `advanceLevel`
    additions are one extra line each, easy to copy-paste wrong.
    Verify by checking that `pickups.length` matches
    `pickupSpawns.length` after each transition.
  - **Picking tier before kind, then reversing later.** The
    seeded-PRNG contract is order-sensitive. If the implementer
    refactors AC #7 and reorders the two `rand()` calls, the same
    `?seed=` URL produces a different layout — a silent breaking
    change to bug-report URLs. Don't reorder.
  - **Stacking pickup pops at the same cell.** Multiple grabs at
    the same `(p.x, p.y)` create overlapping pops that visually
    blob into illegible text. The single-pass `applyPickups` plus
    distinct per-cell spawns (AC #7's `taken` Set + cell-shuffle
    pickup loop only picks one entity per cell anyway) make this
    a non-issue in practice.
  - **Pickup sprite renders at eye level.** If the implementer
    centers the visible pixels in rows 4-11 instead of 8-15, the
    pickup looks "floating in space" because `drawSprites` centers
    the sprite at halfH. Bias the pixels low (AC #3).
  - **`MAX_PICKUPS` clamp applied too early.** The cap is across
    the whole dungeon, applied during the room loop. Two correct
    places to check: (a) outer loop guard
    `newPickupSpawns.length < MAX_PICKUPS`, (b) inner loop guard
    same condition. Both are needed because the per-room count is
    rolled before the cap check.
  - **Touching the canvas-text fillStyle / textAlign /
    textBaseline without restoring.** `drawPickupPops` borrows the
    same restore-defaults pattern from `drawKillPops`
    (`ctx.textAlign = 'left'; ctx.textBaseline = 'top';` at the
    end). Skip that and downstream HUD strip text renders
    centered, which looks wrong.
  - **Pickup grab fires on the death frame.** `applyPickups`
    early-returns on `player.hp <= 0`. The `update()` death
    early-return already covers this from above, but the local
    guard documents intent and survives reorderings.
  - **Pickup grab triggers the kill-pop renderer.** Different
    array (`pickupPops` vs `killPops`), different renderer
    (`drawPickupPops` vs `drawKillPops`). Don't push to
    `killPops` from `applyPickups`.
