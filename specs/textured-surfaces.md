# Textured Surfaces — Walls, Floor, and Ceiling Get Pixel Art

## Goal

Replace the flat solid colors used for walls, floor, and ceiling with procedurally-generated 64×64 pixel-art textures, sampled with the standard raycaster u/v formulas. This is the single biggest visual upgrade we can make to the renderer and is the foundation that the lighting / atmosphere spec will tint on top of. Textures are baked into typed arrays at startup from pure code — no asset files, no network.

## Acceptance Criteria

1. **Single-file constraint preserved.** Still one `index.html` at the repo root, no build, no external assets, no network requests. All texture pixels are generated by JS at startup.
2. **Texture registry.** A `TEXTURES` module-scope object holds at least four 64×64 textures, each as a `Uint32Array(64*64)` of packed RGBA (same `rgba32` packing as the existing renderer). Required entries:
   - `brick` — used for `MAP` cell value `1` (the existing red-brick walls).
   - `stone` — used for `MAP` cell value `2` (the existing blue-stone walls).
   - `floor` — used for the floor (replaces the flat `FLOOR_C`).
   - `ceiling` — used for the ceiling (replaces the flat `CEIL_C`).
   The texture size constant `TEX_SIZE = 64` is shared.
3. **Procedural generators.** Each texture is built by a pure function called once at startup; no `await`, no IO, no `Image`/`fetch`/`<img>`. Generators may use `Math.sin`/`Math.cos`/`Math.hypot`/`Math.floor` and a small seeded LCG (see Design Notes) — **`Math.random()` is forbidden** so renders are byte-identical run to run. Generators must be self-contained (no shared mutable state between calls).
4. **Visual identity per texture.**
   - `brick` — visible brick rows (~8 px tall) with darker mortar lines, and per-brick lightness variation so individual bricks read distinctly. Dominant hue stays in the existing red/orange family.
   - `stone` — irregular noisy stone, dominant hue in the existing blue/grey family, no obvious horizontal banding.
   - `floor` — tiled stone or wood-plank pattern with subtle per-tile variation. Visible from any angle without obvious seams at cell boundaries.
   - `ceiling` — darker than the floor; can be a coarser stone pattern or a flat dark texture with subtle noise. Does not need to be as detailed as the floor.
   "Reads distinctly" is the bar — a player should be able to tell brick from stone at any in-game distance, not just up close.
5. **Wall texture mapping.** For each rendered column, compute the texture u-coordinate from the wall hit:
   - If `side === 0`: `wallX = player.y + perpWallDist * rayDirY`.
   - If `side === 1`: `wallX = player.x + perpWallDist * rayDirX`.
   Then `wallX -= Math.floor(wallX)`; `texX = (wallX * TEX_SIZE) | 0`. Mirror `texX` (`TEX_SIZE - 1 - texX`) on the standard side/dir cases so adjacent cells line up — see Design Notes for the exact rule.
6. **Wall texture sampling.** The inner per-row loop samples the texture column at `texX`, with `texY` stepping at the standard rate of `TEX_SIZE / lineHeight` per screen-pixel row. Use a fixed-point integer step (`step = (TEX_SIZE << 16) / lineHeight | 0`, accumulator advances by `step`) or a float — both are acceptable as long as ≥ 30 FPS at 480×270 holds.
7. **Floor and ceiling texturing.** For every screen row `y` in `[HALF_H, H)`:
   - Compute `rowDist = H / (2*y - H)` (perpendicular distance to that floor row).
   - Compute the world position at the leftmost ray (`cameraX = -1`) and rightmost ray (`cameraX = 1`) at that distance.
   - Step linearly across the row, sampling `floor` at `(floorX & (TEX_SIZE-1), floorY & (TEX_SIZE-1))` (with `floorX = worldX * TEX_SIZE | 0` etc.).
   - Mirror the sampling for the symmetric ceiling row at `H - 1 - y`, sampling the `ceiling` texture.
   The standard Lode-Vandevenne floor-cast formulation is fine; `& (TEX_SIZE-1)` requires `TEX_SIZE` to be a power of two (it is, since 64).
8. **Side darkening preserved.** When `side === 1` (a Y-side hit), the sampled wall pixel is darkened by ~40% (multiply each channel by 0.6 before writing). This matches the existing solid-color renderer's behavior and gives the corners-and-edges depth cue.
9. **Distance shade preserved.** The existing `shade = Math.min(1, 5 / (d + 0.5))` multiplier still applies to walls, *and now also to floor/ceiling* using each row's `rowDist`. Without it, far-away floor pixels look flat and reveal the texture as static. (If `atmosphere-lighting` ships first or is implemented in the same window, see #14 for how to compose.)
10. **Wall type → texture mapping.** `MAP` cell value `1` → `brick`, `2` → `stone`. The renderer must look up the texture from a small `WALL_TEX = { 1: TEXTURES.brick, 2: TEXTURES.stone }` map (or an array indexed by wall type) — no hardcoded `if (wallType === 1)` branch in the inner loop. Adding a third wall type later should be a one-line change in `WALL_TEX`.
11. **Channel-multiply helper for shade and side.** A single inline helper `shadePixel(rgba, mulR, mulG, mulB)` (or an inlined sequence) applies the side-darkening and distance shade to a packed RGBA in one place. Per-channel extract → multiply → repack. Do not branch inside the per-pixel loop on whether to apply shade — always apply with `mul = 1.0` when no shading is wanted.
12. **Performance.** At 480×270 with the existing 16×16 map and the player walking through the room, the renderer must hold **≥ 30 FPS** on the same hardware that meets the existing target. Floor/ceiling casting per row is the most expensive new cost; keep the inner loop branch-free and use `Uint32Array` reads/writes only — do not extract to floats per pixel.
13. **No new console errors.** A 60-second walk through every reachable cell of the map produces zero errors and zero warnings.
14. **Composition with `atmosphere-lighting`.** If the atmosphere spec has already shipped when this one is implemented, sample the texture *first* (producing a packed RGBA per pixel) and then run the existing fog/vignette pass on the textured pixel — do not bypass either. If atmosphere has not shipped, the existing distance-shade is the only post-effect. The two specs are independent of order; whichever lands second composes cleanly on top.
15. **Minimap untouched.** If `polish-audio-minimap` has shipped, its 96×96 corner minimap continues to draw walls as solid color cells (not textured). Texturing is a 3D-view concern only.

## Out of Scope

- Loading external image files (PNG/JPG/etc.) — the project's no-asset rule still holds.
- Bilinear / trilinear filtering. Nearest-neighbor sampling only; the pixelated look is intentional.
- Mipmapping. Distance shade does the work of hiding aliasing in the far field.
- Animated textures (flowing water, scrolling lava, flickering panels).
- Light maps, baked global illumination, or per-cell ambient values.
- Different floor / ceiling textures per region (single-floor and single-ceiling textures are fine for now).
- Door textures, transparent walls, or thin walls.
- A texture editor or hot-reload tooling.
- Sprite (enemy) texturing — sprites are out of this spec; their renderer comes from `sprite-enemies` and stays unchanged.
- Any change to the `MAP`, `MAP_W`, `MAP_H`, `player`, `castColumn`, or movement / collision code beyond what's strictly necessary to plumb texture sampling into `render`.

## Design Notes

- **Symbols this spec depends on / will modify:**
  - `castColumn(x)` — its return shape (`{ perpWallDist, side, wallType }`) is sufficient *if* you also have access to `rayDirX`, `rayDirY` to compute `wallX`. Either extend the return to include those, or recompute them in the caller from `x` and the player camera vectors. Either is fine; pick the cheaper one and stay consistent.
  - `render()` — replace the inner column-fill loop and the `fillBackground()` call.
  - `fillBackground()` — gets replaced by the per-row floor/ceiling cast (or stays for the upper rows above any visible wall, but it's cleaner to delete it).
  - `rgba32`, `buf32`, `buf8`, `HALF_H`, `W`, `H` — keep using the existing pixel-buffer infrastructure.
  - `CEIL_C`, `FLOOR_C` — can be deleted once floor/ceiling are textured.
  - `zBuffer` — unchanged; sprites still need it.
- **Seeded LCG sketch** (deterministic, no `Math.random`):
  ```
  function lcg(seed) { let s = seed >>> 0; return () => (s = (s * 1664525 + 1013904223) >>> 0) / 4294967296; }
  ```
  Each generator gets its own `lcg(SOME_CONSTANT)` so textures don't share noise.
- **Texture column sampling sketch:**
  ```
  // Inside render() per column x:
  const hit = castColumn(x);
  const tex = WALL_TEX[hit.wallType] || TEXTURES.brick;
  const rayDirX = player.dirX + player.planeX * (2 * x / W - 1);
  const rayDirY = player.dirY + player.planeY * (2 * x / W - 1);
  let wallX;
  if (hit.side === 0) wallX = player.y + hit.perpWallDist * rayDirY;
  else                wallX = player.x + hit.perpWallDist * rayDirX;
  wallX -= Math.floor(wallX);
  let texX = (wallX * TEX_SIZE) | 0;
  if ((hit.side === 0 && rayDirX > 0) || (hit.side === 1 && rayDirY < 0)) {
    texX = TEX_SIZE - 1 - texX;
  }
  const lineHeight = (H / hit.perpWallDist) | 0;
  const drawStart = ((H - lineHeight) >> 1);
  const drawEnd   = drawStart + lineHeight;
  const yClipStart = Math.max(drawStart, 0);
  const yClipEnd   = Math.min(drawEnd, H);
  const step  = (TEX_SIZE << 16) / lineHeight | 0;
  let texPos  = ((yClipStart - drawStart) * step) | 0;
  // ... per-pixel inner loop reads tex[texY*TEX_SIZE + texX] and applies shade ...
  ```
- **Floor/ceiling cast sketch** (per-row, runs once per `y` in `[HALF_H, H)`):
  ```
  const rayDirX0 = player.dirX - player.planeX;
  const rayDirY0 = player.dirY - player.planeY;
  const rayDirX1 = player.dirX + player.planeX;
  const rayDirY1 = player.dirY + player.planeY;
  for (let y = HALF_H; y < H; y++) {
    const p = y - HALF_H;
    const rowDist = HALF_H / p;
    const stepX = rowDist * (rayDirX1 - rayDirX0) / W;
    const stepY = rowDist * (rayDirY1 - rayDirY0) / W;
    let fx = player.x + rowDist * rayDirX0;
    let fy = player.y + rowDist * rayDirY0;
    const shade = Math.min(1, 5 / (rowDist + 0.5));
    // ... loop x from 0..W: sample floor at (fx,fy), sample ceiling at H-1-y, advance fx/fy ...
  }
  ```
  Note that `p = 0` at the horizon row (`y === HALF_H`); guard with `if (p === 0) continue;` or start at `HALF_H + 1`. The horizon row stays whatever color the wall behind it produces.
- **Mirror rule for `texX`** (per the standard Lode-Vandevenne formulation): mirror when `(side === 0 && rayDirX > 0)` OR `(side === 1 && rayDirY < 0)`, so adjacent walls' textures meet at corners without flipping.
- **Don't branch the inner loop on `wallType`.** Look up the texture once outside the column's per-pixel loop.
- **Stay in `Uint32Array` land for fast paths.** Per-pixel channel extraction (`r = c & 0xff`, etc.) plus repack is cheap and unavoidable for shading. Avoid float intermediates per pixel — multiply integer channels and `| 0`.

## Agent Notes

- Read `AGENTS.md` and `specs/raycaster-mvp.md` first. Make all changes inside the assigned worktree only.
- Single-file, vanilla JS, no build, no `package.json`. Same constraint as every previous spec.
- The existing code in `index.html` already has the `castColumn` / `render` / `fillBackground` structure. The diff for this spec is:
  1. Add `TEX_SIZE`, `TEXTURES`, `WALL_TEX` plus four generator functions.
  2. Call the generators once at startup to fill `TEXTURES`.
  3. Replace `fillBackground()` with a per-row floor/ceiling cast.
  4. Replace the per-column wall fill (`buf32[i] = c`) with a per-pixel sampled write.
  5. Apply distance + side shade through the helper.
  6. Delete `CEIL_C` / `FLOOR_C` (or keep them only as fallbacks if you genuinely need them — usually not).
- **Common pitfalls:**
  - **Texture seams at corners** — the `texX` mirror rule (#5 / Design Notes) is the standard fix. If your bricks visibly flip-flop at every corner you forgot the mirror.
  - **Floor and ceiling sliding past each other when the player rotates** — almost always a sign the per-row stepX/stepY weren't recomputed against the rotated `rayDirX0/1`, `rayDirY0/1`. Recompute every frame, not at startup.
  - **`p = 0` divide at the horizon** — the horizon row needs special-casing; otherwise `rowDist` is `Infinity` and the floor pixels at `y === HALF_H` are garbage / NaN.
  - **`Math.random()` in a generator** — forbidden by #3; the textures are supposed to be byte-identical across runs so visual regressions are detectable. Use the seeded LCG.
  - **Per-pixel float work in the inner loop** — measure your FPS before declaring done. The floor cast adds `H/2 * W = 64,800` pixel sampling operations on top of the existing column work; if you do float math per pixel you will fall under 30 FPS on slow hardware.
  - **Forgetting the side shade** — if you remove the side shade because "the texture has its own variation," walls look flat and depth cues vanish. Keep it.
- Smoke-test before reporting:
  - Serve the file (`python3 -m http.server`) and walk the entire map. Confirm: brick reads as brick at any distance, stone reads as stone, floor/ceiling are clearly textured, walls don't seam-flip at corners, FPS counter stays ≥ 30 throughout, no console output.
  - Stand close to a stone block in a corner and rotate 360°. The texture should not jitter, slide, or wrap discontinuously.
  - Compare the first frame to a reference run (re-run the page) — pixel output must be byte-identical (textures are deterministic).
  - Run `node --check` against the extracted `<script>` body.
- This spec touches the hottest inner loop in the renderer. Keep the diff focused: do not reorganize unrelated code, do not introduce a "TextureSet" class, do not split into multiple files. The next spec (`atmosphere-lighting`) will compose on top of whatever you ship here.
