# [Project Name] – Agent Notes

## Spec-Driven Development

New features and improvements are described in **spec files** under `specs/`.
Each spec is a self-contained task for an agent to implement autonomously.

- **Dispatchable specs** belong in `specs/`. These are the specs discovered by
  `spec list`, shown by `spec watch`, and eligible for `spec auto run`.
- **Task specs** under `specs/tasks/` are for the `spec task` flow and are not
  part of normal top-level spec discovery.

### The `spec` CLI

The `spec` command is the primary interface for humans and agents.

**Primary commands:**

| Command | What it does |
|---------|-------------|
| `spec create [--spec ID]` | Author a new spec interactively |
| `spec implement --spec ID [--agent claude\|codex] [--review-agent claude\|codex]` | Start/resume implementation workflow |
| `spec status --spec ID` | Show run state and gate status |
| `spec list [--all]` | List specs with status and dependencies |
| `spec show --spec ID` | Display a spec's content |
| `spec report --status ok\|blocked\|error\|needs-input` | Report implement-phase completion |
| `spec clean --spec ID` | Remove worktrees and branches |
| `spec task [--agent claude\|codex] [--review-agent claude\|codex]` | Describe and execute a quick task |

### Worktree-Only Editing Rule

**Never edit files in the main worktree.** The main worktree is for
orchestration only — running `spec implement`, `spec status`, etc. All file
changes must happen in a dedicated worktree.

### Implement Agent Contract

When launched by the orchestrator for `implement`, follow this contract:

1. **Read context first** — read the spec file and `AGENTS.md` before editing.
2. **Stay in the provided worktree** — do not switch branches or start another run.
3. **Apply only this attempt's scope**:
   - Initial/retry: implement remaining spec work
   - Verify retry: fix the failing gate output provided by orchestrator
   - Review retry: address unresolved review findings only
   - Merge-conflict retry: resolve merge conflicts only
4. **Run verify gates locally** before reporting.
5. **Do not run orchestrator lifecycle commands** (`spec implement`,
   `spec phase`) or publish/merge/cleanup actions from inside the
   implementation session. `spec report` is the exception — it is required
   (see step 6).
6. **Report completion before exit**:
   ```bash
   spec report --status ok|blocked|error|needs-input --summary "..."
   ```
   Use `needs-input` when the spec is genuinely ambiguous and a wrong guess
   would waste retry cycles. Describe the ambiguity and include specific
   options when possible.
   Wait for `Completion recorded for <spec-id>:` before exiting.

### Branch and Worktree Conventions

| Type | Branch | Worktree |
|------|--------|----------|
| Spec implementation | `code/<spec-id>--<run-token>` | `.worktrees/code-<spec-id>--<run-token>/` |
| Task | `task/<slug>--<token>` | `.worktrees/task-<slug>--<token>/` |
| Spec authoring | `spec/<spec-id>` | `.worktrees/spec-<spec-id>/` |

## Asset Baking

Every pixel-art sprite the game draws — enemies, pickups, the exit pillar,
projectiles, the three weapon viewmodels and the two muzzle-flash frames —
is **PNG-sourced**, not hand-written in `index.html`. Source art lives in
`assets/sprites/` as 8-bit RGBA PNGs of any rectangular size. The PNGs are
the sole source of truth; git history is the record of the pre-pipeline
procedural art (there is no bootstrap mode).

**Manifest:** `MANIFEST` in `tools/bake-sprites.mjs` is the only list of
baked sprites — one `{ file, binding, w, h }` entry per PNG. `binding` is
the `const` name the generated region declares (`impFrame1`, `GUN_SPRITE`,
`FLASH_FRAME_1`, …) and is what `SPRITES` / `WEAPONS` / `drawGunViewmodel`
consume. The bake fails if a listed PNG is missing, is not 8-bit RGBA, or
has dimensions that differ from its manifest entry. To add a sprite: drop
the PNG in `assets/sprites/`, add a manifest row, `make bake`, then
reference the binding.

**Encoding:** for each entry the region carries one object literal
`{ w, h, pal, rle }`. `pal` is the frame's distinct non-zero `rgba32` words
sorted ascending (≤ 255 colours); `rle` is base64 of `(runLength, index)`
byte pairs over the row-major index stream (`0` = transparent,
`k` = `pal[k - 1]`). A tiny synchronous `inflateSprite` in the region turns
each literal into a `Uint32Array` with own `.w`/`.h`. No `Image()`, `fetch`,
`<canvas>` decode or `await` — startup stays synchronous and `index.html`
remains a single file that opens over `file://`.

**Sentinel contract:** `tools/bake-sprites.mjs` rewrites **only** the lines
strictly between these two markers and leaves every other byte of
`index.html` untouched (the rewrite is deterministic — manifest order,
fixed formatting — so re-running it produces no diff):

```
// <BAKED_SPRITES_BEGIN> generated by tools/bake-sprites.mjs — do not edit by hand
...generated...
// <BAKED_SPRITES_END>
```

Never hand-edit between the markers. `make bake` is the only writer.

**Targets:**

| Target | What it does |
|--------|-------------|
| `make bake` | `node tools/bake-sprites.mjs` — decode the manifest PNGs and rewrite the region |
| `make check` | `node tools/bake-sprites.mjs --check` — exit 1 naming stale bindings if a rebake would change `index.html`; writes nothing |
| `make preview` | `node tools/bake-sprites.mjs --preview <tmp>/sprites-preview.png` — contact sheet of every manifest sprite (4× nearest-neighbour on a grey checkerboard, 8 px gutter, rows wrap at 1024 px) plus a legend on stdout |
| `make screenshot` | best-effort headless Chromium screenshot of the first frame; may fail in sandboxes and is not part of `check` |
| `make serve` | `python3 -m http.server` from the repo root |

**Authoring art without a pixel editor (`--dump` / `--encode`):** the
script round-trips a PNG through an editable text format, so an agent can
redraw a sprite by editing text and then look at the resulting PNG and the
preview sheet:

```
node tools/bake-sprites.mjs --dump assets/sprites/vm_pistol.png > scratch/pistol.txt
# edit scratch/pistol.txt
node tools/bake-sprites.mjs --encode scratch/pistol.txt assets/sprites/vm_pistol.png
make bake && make check
```

The text format is: `#` comment lines and blank lines are ignored; palette
lines are `<symbol> <r> <g> <b>` with a single non-space, non-`.` character
symbol; a `---` line separates the palette from the pixel rows; every row
has the same length and `.` is transparent. `--dump` assigns symbols in
order of first appearance from `A–Z a–z 0–9 @#$%&*+=?!~^<>:;,/|` (76
colours max); `--encode` errors on ragged rows or unknown symbols and takes
the image dimensions from the rows. The module also exports `MANIFEST`,
`encodePNG`, `decodePNG`, `pngToWords`, `wordsToText` and `textToWords`
for scratch scripts; the CLI only runs when the file is executed directly.
Record attribution for any non-original art in `assets/CREDITS.md`.
